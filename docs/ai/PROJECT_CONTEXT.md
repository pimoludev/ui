# Pimolu UI — technical context

Updated: 2026-10-22. This folder describes the local repository and is the
starting point for the next sessions. Re-read the relevant source before any
change: these notes do not replace it.

## Verified state

- pnpm and TypeScript monorepo, with the React source library in
  `registry/react`, the shared CSS in `packages/web-styles`, and tokens and
  themes in `packages/design-tokens` and `packages/themes`.
- Two colour modes (`light`, `dark`) plus `system`; seven presets: `default`,
  `monochrome`, `cartoon`, `glass`, `luxury`, `neo-brutalism` and `adaptive`
  (candidate palette, not yet adopted as Default).
- 129 React component families exported by `registry/react/index.ts`, each shown
  in the playground. `examples/nextjs` illustrates the App Router integration.
- Three design dimensions are independent of the preset: radius
  (`data-pimolu-radius`), density (`data-pimolu-density`) and a brand colour
  carried by `PimoluProvider`.
- `apps/website` is the Next.js App Router site: workspace integration,
  homepage, guides under `/docs`, an illustrated catalog and **129 live component
  references** under `/components` and a development-status `/releases` page.
  All families have curated examples, generated APIs, usage and accessibility notes.
  The original twenty are authored standalone; the additional 109 use curated
  Playground compositions with standalone overrides when needed. Preview settings
  are isolated and shareable. Old docs component URLs redirect permanently.
  See `apps/website/IMPLEMENTATION_PROGRESS.md` for actual checks and screenshots.
  Playwright plus Chromium/Firefox/WebKit are installed with maintainer approval;
  no GitHub CI was enabled. See `apps/website/ACCESSIBILITY_AUDIT.md` for the exact
  coverage, public-library findings and remaining assistive-technology work.
  APIs, examples, demo modules and search data are generated by `docs:generate`.
  Run the website's own typecheck/lint/test/build/browser checks separately from
  root verify. The remaining examples and non-React registries are placeholders.
- `@pimolu/react`, `@pimolu/core`, `@pimolu/themes` and `@pimolu/web-styles` are
  private and are not yet a publishable npm distribution.
- GitHub CI stays disabled in `.github/workflows/ci.yml.disabled`. The local
  `.githooks` and `pnpm verify` are the checks in service.

## Vision expressed by the maintainer

One shared visual identity across React, Next.js, React Native, Angular,
Electron and eventually HTML/CSS through a CDN. Longer term: public
documentation, developer tooling, AI integrations and MCP. Those targets are not
features present in the repository.

### Website reader experience

The header and favicon share the outlined Georgia Italic p in `apps/website/app/icon.svg`.
`SiteSearchProvider` owns the single global Dialog/Command search and Ctrl/Cmd K shortcut;
do not add a second listener in DocsShell. Playwright uses localhost to match Next's dev origin.
Primary and supplementary examples use Pimolu Preview/Code tabs. The actual Tabs demonstration
runs in an isolated preview document to prevent the outer tab styles from changing its variants.
`ScrollOutline` controls TableOfContents for catalogue categories and article sections; article
outlines are keyed by route. Application-layout CSS details are not shown to readers.
`SiteAppearance` owns header preset selection and the light/dark icon toggle; device mode remains
available in its popup. `/themes` redirects to `/docs/theming`. Search and sitemap have 152 destinations.
The docs generator runs `scripts/simplify-example.mjs` on all 516 copied examples: variant maps are
expanded at build time, Playground layout classes become Tailwind utilities and sibling sections
receive a gap. Supplemental previews render the same generated modules. Tests compile every copied
snippet as an independent TypeScript module. TabsDemo owns presentation controls; TabsExample is
the documented usage. Official component sources, CSS and presets are unchanged by this iteration.

### SplitButton positioning and source formatting

DropdownMenu passes its logical start/end alignment to `registry/react/internal/use-anchored-position.ts`
before viewport clamping. Do not subtract menu width after clamping: SplitButton end-aligned menus
were being shifted out of view. Other anchored consumers retain centered alignment by default.
DropdownMenu focuses the first enabled command from its actual portal mount callback, with
preventScroll, rather than an effect that can run before the portal exists.

Website examples also run through `apps/website/scripts/format-example.mjs` (syntax-aware wrapping
and TypeScript indentation). All 516 outputs must be stable, independently compilable and have no
line over 140 characters. Preserve the exact values of strings and embedded assets when wrapping.
A viewport-edge SplitButton demonstration is in its Playground page; the website browser regression
checks menu visibility, disabled commands, initial focus, Escape and RTL.

### Website demo navigation and compact appearance (2026-10-22)

`readyExample` in `apps/website/components/docs/example-ready.tsx` provides the common website-only
link boundary for all 516 examples. It cancels site/external navigation, including React portals,
without stopping component event handlers; valid example-local fragments and genuine downloads
remain functional. Keep this mechanism out of the generated copyable snippets and public library.
The site header is sticky; section/sidebar/outline offsets account for its height. The appearance
popup now shows seven labelled color circles instead of cards. RSS remains `/blog/feed.xml`.
See the latest website progress entry for executed checks and screenshot scope.


### Branded media and cached Image hydration (2026-10-22)

The website uses original assets under `apps/website/public/images/`, and audio from `public/sounds/`.
`apps/website/scripts/website-demo-assets.mjs` is shared by both docs generators; do not patch generated
sources or replace intentional missing-image fixtures. Playground assets remain independent. Catalog
captures stay real component renders. The Image registry component now checks the actual image element
for successful decoding after hydration/source changes, preserving forwarded refs and native callbacks.
The homepage no longer needs a client-only image wrapper; the Playground Image page demonstrates cache
remounts. See the newest website IMPLEMENTATION_PROGRESS entry for executed checks and exact coverage.
