## Verified state

- pnpm and TypeScript monorepo, with the React source library in
  `registry/react`, the shared CSS in `packages/web-styles`, and tokens and
  themes in `packages/design-tokens` and `packages/themes`.
- Two colour modes (`light`, `dark`) plus `system`; seven presets: `default`,
  `monochrome`, `cartoon`, `glass`, `luxury`, `neo-brutalism` and `adaptive`
  (candidate palette, not yet adopted as Default).
- 129 React component families exported by `registry/react/index.ts`, each shown
  in the playground. `examples/nextjs` illustrates the App Router integration.
- Three design dimensions are independent of the preset: radius
  (`data-pimolu-radius`), density (`data-pimolu-density`) and a brand colour
  carried by `PimoluProvider`.
- `apps/website` is the Next.js App Router site: workspace integration,
  homepage, guides under `/docs`, an illustrated catalog and **133 live component
  references** under `/components` and a development-status `/releases` page.
  All families have curated examples, generated APIs, usage and accessibility notes.
  The original twenty are authored standalone; the additional 109 use curated
  Playground compositions with standalone overrides when needed. Preview settings
  are isolated and shareable. Old docs component URLs redirect permanently.
  See `apps/website/IMPLEMENTATION_PROGRESS.md` for actual checks and screenshots.
  Playwright plus Chromium/Firefox/WebKit are installed with maintainer approval;
  CI now runs these checks as described below. See `apps/website/ACCESSIBILITY_AUDIT.md` for the exact
  coverage, public-library findings and remaining assistive-technology work.
  APIs, examples, demo modules and search data are generated by `docs:generate`.
  Run the website's own typecheck/lint/test/build/browser checks separately from
  root verify. Other examples and non-React registries are not implemented yet.
- The five library packages (`@pimolu/design-tokens`, `@pimolu/themes`,
  `@pimolu/core`, `@pimolu/react`, `@pimolu/web-styles`) are published on npm
  at `0.1.0-beta.3.1`; both `latest` and `beta` dist-tags point to it.
  `@pimolu/react` is a single ESM bundle with `"use client"` and declarations;
  `@pimolu/core` compiles to ESM. Install the beta with
  `pnpm add @pimolu/react@beta @pimolu/web-styles@beta`. The website stays
  private and has no public preview deployment.
- The release version is chosen by `.agents/skills/release-manager` from the
  commit range and the audit state. `CHANGELOG.md` records the preview and its
  known limits.
- GitHub CI is enabled in `.github/workflows/ci.yml`: Node 24 jobs run library
  verification and website production checks, including three-engine Playwright.
  `pnpm build:website` builds all workspace assets before Next.js;
  `pnpm start:website` honors the host PORT. Canonical domain: https://pimolu.com.
  Local hooks remain active; CI does not deploy.

## Vision expressed by the maintainer

One shared visual identity across React, Next.js, React Native, Angular,
Electron and eventually HTML/CSS through a CDN. Longer term: public
documentation, developer tooling, AI integrations and MCP. Those targets are not
features present in the repository.

### SplitButton positioning and source formatting

DropdownMenu passes its logical start/end alignment to `registry/react/internal/use-anchored-position.ts`
before viewport clamping. Do not subtract menu width after clamping: SplitButton end-aligned menus
were being shifted out of view. Other anchored consumers retain centered alignment by default.
DropdownMenu focuses the first enabled command from its actual portal mount callback, with
preventScroll, rather than an effect that can run before the portal exists.

Website examples also run through `apps/website/scripts/format-example.mjs` (syntax-aware wrapping
and TypeScript indentation). All 532 outputs must be stable, independently compilable and have no
line over 140 characters. Preserve the exact values of strings and embedded assets when wrapping.
A viewport-edge SplitButton demonstration is in its Playground page; the website browser regression
checks menu visibility, disabled commands, initial focus, Escape and RTL.

## Touch scrolling (2026-10-25)

Select now selects on a completed click/tap and only tracks mouse hover; native
pans do not select or scroll the active option into view. Opening it explicitly
focuses the trigger (Safari/WebKit keyboard dismissal). PhoneInput and ThemeBuilder
inherit this fix. Cascader and TreeSelect also distinguish mouse hover from touch
contact, including TreeSelect branch-arrow panning. Three long-list compositions
are demonstrated in both playground and website supplements.

Shared floating placement caps initial width to the viewport, including before a
portal is measured. Select scroll padding keeps its final row visible in a short
landscape viewport. Shared consumers' status badges use explicit overrides for
this internal dependency change. See apps/website/e2e/touch-options.spec.ts for the actual
browser matrix and apps/website/IMPLEMENTATION_PROGRESS.md for validation limits: native touch
pans use Chromium CDP, not physical-device or Firefox/WebKit touch emulation.

The extended mobile review also fixed RangeSlider track activation (completed
tap instead of initial contact), Carousel RTL scroll/index/keyboard alignment,
and Slider/RangeSlider RTL fill direction. Private inherited direction variables
use explicit dir attributes because the website CSS optimizer rewrites :dir()
to language-only selectors. FileManager offers an explicit single-selection Open
action, avoiding reliance on double-tap. Signature Clear/Undo finish valid touch
taps even after a canvas stroke suppresses the browser's compatibility click;
cancelled/moved contacts and duplicate clicks are ignored. Playground examples,
website usage notes and e2e/mobile-surfaces.spec.ts cover these behaviors.
